First run

Start with the idea, not a perfect prompt.

Choose where the questions come from, then Start with voice or Type instead. A rough opening statement is enough. The app saves the conversation on this device and writes the result as portable Markdown.

Open IdeaForge Choose a provider
You do not need to prepare a brief first. The opening question is always the same and does not call a model: In a sentence or two — what’s the idea? A rough statement is enough to begin.

Before you start

What the first interview needs
Item What to prepare
The app Open the hosted app, an installed copy, or a locally served copy. Do not open index.html with file://; modules, IndexedDB, and the service worker need a real web origin.
A question provider Choose a hosted provider, a supported local model server, or the built-in Claude viewer option when it is available. See Providers for the differences.
Credentials or a local model Hosted providers normally need an API key. Local providers need a loopback server address and a model name. Use a scoped, expiring API key rather than a primary account key. Which models run is yours to choose on the same screen. Hosted presets supply model defaults; a local server needs a model you have installed.
Voice, if wanted Use a working browser recogniser or configure hosted transcription. Spoken replies default to the browser voice, with a picker and preview. Both are optional: Type instead starts without opening the microphone.
On a shared device, treat saved interviews as personal files. Ideas and credentials are stored for this browser profile. Use Forget my key when the key should no longer remain on the device, and export or delete conversations as appropriate.

Configure the setup screen

The provider and its key or address, Spoken replies choice, Dictation, finish word and both start buttons stay outside the expandable sections. Open the extra options only when you want to change them.

  1. Choose where the questions come from. Pick an inference provider from the first list. The fields below change to match: hosted providers show an API-key field, local providers show a server address, and both offer two model fields under Model options. This section starts collapsed for hosted providers and opens automatically for local ones.
  2. Enter the required connection details. Paste the provider key, or enter the local server and model. A local address must use localhost or 127.0.0.1. On a phone, those names mean the phone itself, not a computer on the same network.
  3. Open Model options to change the defaults. Model for the questions runs every interview turn and is where the cost is; Model for the wrap-up runs once at the end and is the call that suffers most on a small model. A blank hosted field uses the provider's default, shown as placeholder text. Local providers need an installed question model; a blank wrap-up field then uses that model too. See Providers for the detail.
  4. Choose how to listen and speak. Expand Voice and speaking pace to preview a browser voice and adjust its pace. Selecting OpenAI under Spoken replies opens this section automatically for its separate key, consent and preview. Under Dictation, choose browser recognition, hosted transcription with its key, or Off — keyboard only. The hands-free finish word is configured here too. Optional OpenAI speech has a separate consented check and speech key; it does not supply dictation.
  5. Test the connection. Use Check the key for a hosted provider or Check the connection for a local one. Either makes a real request, and wherever the provider publishes a browser-reachable model list the same request fills the model suggestions. If that list is unavailable, you can still type a known model name.
  6. Start with voice, or Type instead. IdeaForge stores the selected provider settings on this device, creates a new local session and opens the seed question. Voice starts its input/output checks from your tap; Type instead leaves the microphone closed until you request it.

Provider credentials are kept separately from interview records. API keys are encrypted at rest in this browser, while non-secret preferences such as the hands-free finish word, browser voice and speaking pace are device preferences. For the threat model and exact limits of browser storage, read Privacy and security.

Answer the first question

In voice mode, wait until the stage says Listening to you, then answer and end with the configured finish word, normally over. Pause releases the microphone and keeps captured words; Resume needs a tap. Exit returns to the manual interview without skipping or requesting a write-up. See Mobile and voice for pending transcription and device limits.

In the typed interview, describe the idea in your own words. It can be incomplete: the point is to find the missing specifics. Press Send, or use Ctrl+Enter on Windows and Linux or Command+Enter on macOS. A plain Enter remains available for paragraphs.

After the opening answer, IdeaForge asks a follow-up grounded in the conversation. The manual view shows one question, an optional short bridge from the previous answer and sometimes suggestion chips. Voice reads the question and examples in turn, not while listening for another answer.

Use suggestion chips as starting points

Selecting a chip copies its text into the answer box; it does not submit it. Edit the wording until it reflects what you mean, then send it. An unedited chip is treated as model-supplied wording and cannot by itself move a coverage area all the way to covered.

Skip rather than invent

Use Skip this one when you cannot or do not want to answer. The transcript records a real skip rather than pretending you supplied an answer, and the interviewer moves on.

Leave an unfinished answer safely

Text in the answer box is saved after a short pause and is flushed before IdeaForge opens Settings or the Ideas library. Returning to the conversation restores that draft. If browser storage fails, the app reports that the session could not be saved and tells you to export before closing the tab.

Follow the interview without managing it

These controls are in the manual interview. Choose Exit to inspect them from the voice stage; coverage and the stopping rules continue to apply in either mode.

  • The progress meter shows coverage, not a countdown or a quality score.
  • The line below the controls shows the question number and current dimension.
  • Coverage expands to show what is thin, partial, or covered.
  • not relevant removes a dimension from later questions.
  • The write-up button appears after the early part of the interview, so you can stop by choice.

You can write the idea up as soon as the button appears, or continue until the app says there is enough material. The engine also has exhaustion and turn limits so an interview cannot circle for ever. See Interviews and coverage for the full stopping rules.

Create and use the result

  1. Select That’s enough — write it up, or accept the spoken wrap offer in hands-free mode.
  2. IdeaForge makes one final model request for a refined prompt, a short title, explicit assumptions, and unresolved questions.
  3. Read the result. It is shown as a formatted document rather than as Markdown source, and it also contains a coverage table and the full transcript, including skipped and dictated answers. Share, copy and download all hand over the Markdown itself, unchanged, so what you paste into an LLM is the source and not the prose.
  4. Use Share .md, Copy markdown, or Download .md. Choose Ask me more to reopen the same idea, or New idea to return to setup.
A failed wrap-up does not erase the interview. The downloadable document still contains the coverage and transcript, and clearly marks the refined prompt as not generated. You can keep the record, fix the provider problem, and reopen the idea later.

Know what is saved where

First-run data locations
Data Location and behaviour
Interviews and answer drafts IndexedDB in the current browser profile; visible through Ideas.
Inference, transcription and speech credentials Encrypted in IndexedDB; removed by Forget my key.
Finish word, hands-free preference, browser voice and pace Local device preferences, excluded from backups; forgetting a key does not reset them.
Downloaded Markdown or JSON backups Ordinary files outside the app, wherever your browser saves or shares them.

There is no IdeaForge account and no automatic cross-device sync. Before clearing site data or changing devices, use the procedures in Ideas library.
